# GPRO Command Center — приватная синхронизация (план подключения)

## Архитектура
- `fin-plan` (публичный GitHub Pages): интерфейс и программный код, **без личных данных**.
- `gpro-command-data` (приватный репозиторий): JSON-данные, история изменений, материалы.
- Защищённый API (ещё не развёрнут): аутентификация пользователя, чтение/запись в приватный репозиторий через GitHub App с минимальными разрешениями.
- Браузер: локальный кэш и очередь изменений при отсутствии связи. Безопасный API должен обрабатывать конфликты версий, не перезаписывая данные молча.

## Планируемая структура приватного репозитория
```
schema/version.json
profile/finance.json
portfolio/projects.json
projects/<project-id>/strategy.md
projects/<project-id>/tasks.json
projects/<project-id>/finance.json
projects/<project-id>/resources.json
tasks/general.json
strategy/master.md
logs/changes.jsonl
```

## Важные ограничения
1. GitHub Pages **не может** самостоятельно безопасно записывать данные в приватный репозиторий.
2. Нельзя размещать GitHub PAT, private key GitHub App или иной секрет в HTML, JS, JSON, localStorage либо в публичном репозитории.
3. Приватный репозиторий не должен подключаться напрямую из браузера с токеном.
4. Автоматическое сохранение и авторизация **не реализованы**, пока нет приватного репозитория и защищённого API.
5. Текущие данные остаются в localStorage ключ `gpro-command-center`; их можно экспортировать через «Настройки». Нельзя автоматически извлечь пользовательские данные из браузера средствами GitHub-коннектора.
6. GitHub хранит историю изменений, но не заменяет отдельные резервные копии. Вложения большого размера лучше вынести в объектное хранилище в будущем.

## Следующий шаг
Создать на GitHub **Private** репозиторий `koraevgog-create/gpro-command-data` и сообщить о готовности. Затем можно подготовить там безопасную структуру, версионирование схемы, импорт существующей резервной копии и защищённую синхронизацию.

## Формат состояния
Существующий экспорт JSON v2 используется как исходный формат миграции. Перед дроблением данных на файлы необходимо обеспечить обратимую миграцию, сохранение идентификаторов и восстановление из резервной копии.
